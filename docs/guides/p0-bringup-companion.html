Before you start

Files, recording, safety, parts that may be missing

Safety, every time
  • Set the bench supply's voltage and current limit with the output off, before anything is connected. Use the limit given for each stage.
  • If the supply drops into current limit (the CC lamp lights, the voltage falls), switch the output off at once and look for the cause before trying again.
  • Plug and unplug harnesses, the display and the motor only with the supply off.
  • Stage D moves the axis: the rig stands on its tripod, the body is free to turn ±180°, hands and cables are clear of the belt.
  • Power resistors get hot (the 10 Ω load reaches about 26 W): lay them on a metal plate or a tile, not on the mat.

Files

  • On github.com open the repository, click Actions → Firmware and apps → Run workflow. In Use workflow from pick phase-7-prototype (or main once PR 13 is merged), then Run workflow. When it shows a green tick (about 30 minutes), open the run.
  • Download esp32s3-images-and-flasher (web-flasher.html, st-esp32s3-bringup-full.bin, st-esp32s3-system-full.bin) and rp2354a-images (st_rp2354a_bringup.elf, for the Debug Probe route). Unzip both into one folder, e.g. Documents\StarTracker\bringup.
  • Put bench-logger.html (sent with this page) in the same folder. It records the console into files for the measurements.
  • The items q and t, the duration question of k, and the raw logs of o and p exist only in images built from phase-7-prototype after 24 November.

Recording

  • Double-click bench-logger.html: it opens in Chrome or Edge. Type the label P0-A (reducer A; P0-B after sheet R).
  • Connect to the board → pick the board's serial port → the menu appears. Use the key buttons or type into the box. Leave Save each test to its own file ticked: every test ends in a file named e.g. P0-A_k_az_142310.txt.
  • Send me the files in the chat, or copy them into docs/measurements/P0/A/. Take a photo of anything you measure by hand (multimeter, scope) and send it too.

Parts that may still be missing (D83)

  • If the clock U23 (RV-3028) is not fitted yet: item 2 lists 0x52 as MISSING and says FAIL — expected; every other address must be there. Skip item 4.
  • If the GNSS U24 (MAX-M10S) is not fitted yet: skip item 3 and step B8.
  • The display is soldered at build sheet 11, after Stages B and C. Until then item 6 is skipped (or wire the module to J11 with four jumper wires: pin 1 VCC, 2 GND, 3 SCL, 4 SDA).
  • P0 has no battery pack: item c (gauge) and the gauge set-up wait for P1.

Tools by stage

  • A: Magnifier or phone macro, multimeter, bench supply, oscilloscope, spare magnet 6 × 2.5 mm diametric, two short thin wires
  • B: Bench supply with the XT30 bench lead, multimeter, PC with Chrome, USB-A to USB-C data cable, Debug Probe + TC2030 cable (fallback)
  • C: Oscilloscope, 10 Ω 50 W resistor + two 0.5 mm² wires, IR thermometer, 45 W USB-C charger + e-marked cable, FNB58 PD tester, port B load (see C4), multimeter
  • D: Rig on its tripod (sheet 12), the cartridge harness on J7, bench supply up to 3 A

G

Battery gauge in bqStudio (P1)

EV2400 on the pack's blade connector · settings from firmware/config/bq40z50-r2-p50b.csv

  1. Wave 3 brings the EV2400 and the battery board. Install TI Battery Management Studio (bqStudio); plug the EV2400 into the PC.
  2. Wake the new pack first: a 2-cell pack must see a charger on PACK+ (data sheet). Put the pack in the head and plug the 45 W charger into port A for 10 seconds, then take the pack out.
  3. EV2400 SMBus port to the pack's blade connector: SMBD to SMBus data, SMBC to SMBus clock, GND to power −. Nothing on PACK+.
  4. bqStudio → Gauge → it finds bq40z50-R2. Not found: wiring, or wake the pack again.
  5. Commands panel → UNSEAL, then FULL ACCESS (TI's default keys) so Data Memory can be written.
  6. Data Memory → type each name from firmware/config/bq40z50-r2-p50b.csv into the search box, enter its value, press Enter (it writes at once). DA Configuration: tick 2 cells in the bit view.
  7. Chemistry → find Molicel INR-21700-P50B → Program Selected Chemistry. Not in the list: tell me — we log one relaxation and discharge for TI's GPCCHEM.
  8. Commands → RESET. Data Memory → Export → save the golden file (.gg.csv) and send it to me.
  9. LED check: press the pack button: the lit LEDs follow the charge; step the charge by charging and discharging to see positions 1–4 light in order (Phase 4: wiring as TI's module, to be confirmed).
  10. Learning cycle (as TI's guide): Commands → Gauging on; charge full; rest 2 h; discharge at 2 A (C/5) to empty; rest 5 h; charge. Then bring-up menu c: 5.8–8.5 V, −20…60 °C, no safety flags.
